# Translating the studio site

The site in `docs/` is published in five languages as static pages:

| Language | Folder | Strings |
| --- | --- | --- |
| English (source) | `docs/` | `docs/i18n/en.json` |
| Português (Brasil) | `docs/pt-br/` | `docs/i18n/pt-BR.json` |
| Español | `docs/es/` | `docs/i18n/es.json` |
| Français | `docs/fr/` | `docs/i18n/fr.json` |
| Deutsch | `docs/de/` | `docs/i18n/de.json` |

The English pages in `docs/` are the source. `npm run build` fills them from `docs/i18n/en.json` and writes every page again in each language folder, with the same relative path. Never edit a file inside a language folder: it is overwritten on every build.

## Files

- `docs/i18n/languages.json`: the languages, in menu order. The first one is the source and the `x-default` of the hreflang tags. Each entry has `code` (the `lang` and `hreflang` value), `dir` (the folder), `name` (written in that language), `short` (shown in the header) and `og` (the `og:locale`).
- `docs/i18n/<code>.json`: one flat object of `key: string` per language. Every file has exactly the keys of `en.json`, in the same order. Values may hold inline HTML (`<code>`, `&amp;`) and placeholders (`{n}`, `{name}`); a translation keeps both.
- `docs/i18n/changelog/<code>.md`: the translation of `CHANGELOG.md`, with the same releases, sections and items. The changelog page of each language is built from it.

## How a page gets localized

The generator is `scripts/lib/docs.mjs` with `scripts/lib/i18n.mjs`. There is no list of pages: it reads every `.html` file under `docs/`, in any subfolder, except the language folders, `assets/`, `data/`, `vendor/`, `partials/` and `i18n/`. Every page that uses the string files (at least one `data-i18n` or `data-i18n-attr`, which every page with the shared header has) is localized. For each page and language the build:

1. inserts the partials (`<!-- head:start --><!-- head:end -->`, `header`, `footer`), with their links rebased for pages in subfolders, and marks the current nav item (`data-nav` equal to the page name or to its first folder, so `docs/guides/react.html` marks `data-nav="guides"`);
2. replaces the content of each `data-i18n` element and each attribute listed in `data-i18n-attr` with the string of the language, and sets `<html lang>`;
3. points links to shared files (`assets/`, `data/`, `vendor/`, images) back to them, while links to other localized pages stay inside the language folder;
4. writes the canonical link, the hreflang alternates of every language plus `x-default`, `og:url` and `og:locale`;
5. renders the language menu in the header (`<!--lang:menu-->`), the language list in the footer (`<!--lang:list-->`), the first visit script (`<!--lang:detect-->`) and the strings the scripts need (`<!--lang:strings-->`).

## Writing a page

```html
<h2 data-i18n="guides.react.title">React guide</h2>
<p data-i18n="guides.react.lead">Install the package and render your first icon.</p>
<input placeholder="Search" aria-label="Search icons" data-i18n-attr="placeholder:icons.search;aria-label:icons.search">
<title data-i18n="guides.react.meta.title">React guide: glyphfox</title>
<meta name="description" content="..." data-i18n-attr="content:guides.react.meta.description">
<meta property="og:title" content="..." data-i18n-attr="content:guides.react.meta.title">
```

- Write the English text in the page and the same text in `en.json`; the build always takes the value from `en.json`.
- A `data-i18n` element may contain inline markup, but not an element with its own tag name (no `<span>` inside a `data-i18n` `<span>`).
- Code is never translated: `pre`, `code`, `kbd`, `samp`, `var`, `script`, `style` and `svg` are left as they are. Code samples stay code.
- Values that must stay as they are (API values in a select, icon names and tags, file names, a command) go in `<code>` or in an element with `translate="no"`.
- Text in another language on purpose takes a `lang` attribute (the language menu marks each name with its own `lang`).
- Give every page a `<title>`, a meta description and an `og:title`, all with keys, so search results and shared links are translated too.
- Use keys named after the page (`smart.hero.title`, `guides.vue.install`) and reuse the shared ones (`nav.*`, `action.copy`, `axis.*`).

## Pages from other branches

Guides in `docs/guides/`, icon pages in `docs/icons/`, `docs/smart.html`, `docs/native.html`, `docs/labs.html`, `docs/universe.html` and any other page localize on their own once they are merged:

1. use the partial markers so the page gets the header, the footer and the language menus;
2. tag the copy with `data-i18n` and `data-i18n-attr` as above, and add the keys to the five files in `docs/i18n/`;
3. in a subfolder, write links relative to the page (`../icons.html`, `../assets/site.css`); the partials are rebased by the build;
4. pages generated by a script (one page per icon) are written as English pages in `docs/` before the build runs, and the build localizes them like any other page;
5. run `npm run build` and `npm run check:i18n`, then commit the pages of every language folder.

Branches started before this change may still add strings to `docs/assets/js/i18n.js`. When such a branch is merged, keep that file: the build reads it as a fallback for English and Portuguese, and `npm run check:i18n` fails until its keys are moved into `docs/i18n/*.json` (with Spanish, French and German) and the file is deleted. A list such as `LOCALIZED` in `scripts/lib/docs.mjs` is no longer needed.

## Scripts

Site scripts import `t` from `docs/assets/js/app.js`:

```js
import { t, category } from './app.js';
toast(t('toast.copied'));
line.textContent = t('icons.result.count', { n: list.length });
hint.textContent = t(`editor.hint.${tool}`);
label.textContent = category('arrows');
```

The build writes the strings the scripts use into each page as `<script type="application/json" id="gf-strings">`, so `t()` is synchronous and costs no extra request. A key counts as used when a script calls `t('key')`, when it calls ``t(`prefix.${x}`)`` (every key that starts with `prefix.`), or when the key appears as a string literal. Icon categories keep their English id in the data; `category(id)` shows `cat.<id>`.

Diagnostics of the engine (lint messages) are part of the package and stay in English; the notes of Fox-ify are mapped to `foxify.note.*`.

## Language detection and the remembered choice

- On the first visit, the head script picks the first browser language (`navigator.languages`) that the site has, by exact tag or by its primary subtag (`pt-PT` gives Português (Brasil), `es-MX` gives Español), falls back to English, and remembers it in `localStorage` (`gf-lang`).
- Choosing a language in the header menu or the footer list remembers that choice.
- English pages, the `x-default`, send the visitor to the remembered language. Pages in a language folder always show their language, so shared links and search results open as they were sent and crawlers see every version.
- Without JavaScript or storage nothing is redirected and the menus still work (the header menu is a `details` element).
- `404.html` is one page for every address: it picks the language from the folder in the address, then the remembered choice, then the browser.

## Checks

`npm run check:i18n` (also run by `node scripts/build.mjs --check`, `npm run ci` and CI) fails when:

- a string file misses a key of `en.json`, has an extra key or an empty value, or drops a placeholder or an HTML tag;
- a page, a partial or a script uses a key that does not exist;
- a localized page is missing, or has a wrong `lang`, canonical or hreflang set;
- a page in another language has English left outside code: a text or a translatable attribute (`title`, `alt`, `placeholder`, `aria-label`, the meta description and the `og:` texts) that is identical to the English page and has a real word in it. Names (glyphfox, React, SVG and the like), numbers and code shaped tokens (`file+check`, `useMorph`, `arrow-right`) do not count, and neither do values that a translation keeps equal to English on purpose ("Docs", "Props");
- a changelog translation does not match the releases, sections and items of `CHANGELOG.md`;
- `docs/assets/js/i18n.js` still exists.

Each problem names the file and the text, for example `docs/fr/docs.html: English left in <p>: "..."`: add a key, translate it, or mark the text as code.

## Adding a language

1. Add an entry to `docs/i18n/languages.json`.
2. Add `docs/i18n/<code>.json` with every key of `en.json` and `docs/i18n/changelog/<code>.md`.
3. Run `npm run build` and `npm run check:i18n`.
